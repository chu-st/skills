## Начните обычным запросом

> Исследуй, стоит ли нам менять систему поддержки клиентов.
> Используй dual-model-review, вторая модель — Claude Opus.
> Сначала получи независимые ответы, затем проверь существенные расхождения.

> Проверь этот аналитический отчёт через dual-model-review.
> Вторая модель — Codex, модель укажу при запуске. Особенно проверь причинные выводы.

> Помоги сравнить варианты обучения. Второй ответ я принесу из Gemini.
> Подготовь нейтральное задание для отдельного чата и потом сведи результаты.

> Настрой dual-model-review: оркестратор — Claude Fable, вторая — ChatGPT,
> третья — Gemini. По умолчанию используй две модели.

> Прогони этот план в трёх моделях по моим настройкам.

Это пример предпочтений, а не обязательный набор. Можно выбрать других поставщиков,
приложения и модели. Настройка — отдельный режим этого же скилла: агент сохраняет
роли в личном профиле, который переживает обновление пакета. Для разовой задачи
можно назвать модели прямо в запросе, без настройки файла.

| Роль | Две модели | Три модели |
|---|---|---|
| Оркестратор | Задание, собственный ответ, проверка и итог | То же |
| Вторая | Независимый ответ или ревью | То же |
| Третья | Не вызывается | Ещё один независимый ответ или ревью |

Если запрос не задаёт другое число, используется сохранённое; без настройки — две.
Третья модель не становится арбитром: результат определяется фактами, а не большинством.

Можно начать [с одного промпта](prompts/start-ru.md) в любом агенте, который принимает
текст. Для автоматического вызова второй модели нужен доступ к ней. Без него метод
работает через перенос задания и настоящих ответов между выбранными чатами.

## Где это полезно

| Задача | Что проверяет второй взгляд |
|---|---|
| Исследование темы | Полноту аргументов, качество источников, альтернативные объяснения |
| Аналитический отчёт | Знаменатели, причинные выводы, скрытые допущения |
| Выбор решения | Ограничения, компромиссы, условия, при которых выбор нужно изменить |
| План или документ | Пробелы, противоречия, проверяемость обещаний |
| Код | Воспроизводимые дефекты и соответствие требованиям |

## Как устроена проверка

Общий вопрос → независимый ответ → проверка существенных расхождений по источникам
или расчётам → исправленный результат с оставшимися неопределённостями.

Согласие моделей само по себе не доказывает правоту. В методе нет голосования и
обязательной нормы замечаний. Проверяемые факты, гипотезы и предпочтения различаются.
Сбой доступа к модели не считается выполненной проверкой.

## Способы запуска

| Откуда | Вторая модель | Способ |
|---|---|---|
| Claude Code | Пользовательская модель Codex | Встроенный CLI-адаптер |
| Codex | Claude Opus или другой выбранный Claude | Встроенный CLI-адаптер |
| Агент с доступом к модели | Любая доступная модель | Собственный коннектор агента |
| Другой CLI | Модель из его конфигурации | Явно заданный адаптер |
| Любой текстовый чат | Любая модель в другом чате | Ручной перенос задания и ответа |

Gemini и другие провайдеры подключаются через доступный инструмент выбранного
приложения, явно настроенный CLI-адаптер или отдельный чат. Встроенного адаптера
Gemini в этом выпуске нет. Доступ к ChatGPT, Codex и API проверяется отдельно:
скилл не подменяет одно приложение другим и не создаёт учётные записи.

Python нужен только для необязательного CLI-помощника и установщика. Сам метод —
обычный текст. Реально проверенные версии и ограничения см. в [проверке выпуска](docs/validation.md).

## Что вы получаете

Полный [скилл](skills/dual-model-review/SKILL.md), [конфигурацию ролей](skills/dual-model-review/references/configuration.md),
нейтральные задания для моделей, инструкции для исследований, необязательные помощники настройки и запуска и пример с
проверяемой арифметикой. Настоящие результаты прогона не публикуются автоматически.

## Границы

Метод не гарантирует правильность ответа, независимость источников или экономию.
Его полезность проверяется на конкретной задаче. Для сравнения стоимости нужна
проверка против одной модели при сопоставимом бюджете. Вызовы используют ваши
учётные записи и ограничения провайдеров. Пакет не содержит телеметрии и не
отправляет материалы на chu.st.

Ошибку удобно описать через вопрос, использованные модели, наблюдаемый результат
и ожидаемое поведение. Перед публикацией примера удалите личные данные.
