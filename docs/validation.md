# Проверка пакета

## Выпуск 0.4.0: полный цикл, разногласия и настройки

25 сентября 2026 текущий Codex подготовил исходные предложения и координировал
реальные ответы Claude Fable и Gemini Pro через выбранные владельцем способы
доступа. Это проверка конкретного выпуска, а не оценка средней точности метода.

| Участник | Что установлено |
|---|---|
| Текущий Codex | Автор и ведущий; точный идентификатор обслуживающей модели независимо не подтверждён |
| Claude Fable | Запрошено `fable`, провайдер сообщил `claude-fable-5-1`; совпадение семейства |
| Gemini Pro через Antigravity | Явно передан `gemini-3.1-pro-high`; получены настоящие ответы, но CLI не сообщает имя ответившей модели |

Три участника обменивались реальными ответами. Полностью подтверждённая
идентичность всей запрошенной тройки не установлена. Продукт ChatGPT в этом
саморевью не участвовал: текущий Codex был отдельно выбран автором.

Сначала два внешних участника независимо предложили изменения формулировок,
настройки и полного цикла по одному пакету версии 0.3.1 с 14 сценариями.
Ведущий сохранил собственный вариант до получения ответов. Это анализ сценариев,
не проверка автоматического обнаружения скилла в интерфейсе приложения.
В ответах обнаружились ошибки: лишний запуск нескольких моделей для обычного
исследования, предложение сохранять двусмысленное «в следующий раз» навсегда,
а также неверное самообозначение внешнего участника ведущим. Они не приняты.

Затем проведено отдельное исследование разногласий: три первых ответа,
взаимная критика обоих остальных, три авторские доработки, один общий раунд по
четырём оставшимся вопросам и независимые проверки одной общей версии. Получено
десять внешних ответов на пяти стадиях, по одному от каждого рецензента на стадию.
Внешние участники получили одинаковое досье из семи первоисточников, без своего
доступа к поиску. Отбор источников и первичные наблюдения выполнял ведущий.
[Исследовательская записка](disagreement-research.md) отделяет выводы работ,
аналогии из человеческой практики и предложенную процедуру.

На конкретных примерах выявлены тест, не различающий утверждения, выдуманные
показатели производительности, перенос результата одной проверки на непроверенные
версии и рекомендация гибрида только на основании его осуществимости. Ведущий
исправил свой пропуск конкретных примеров и усилил защиту исходных позиций от
искажения в карточках. Локально проверены ошибка синтаксиса литерального вызова и
сконструированный контрпример к выводу о взаимоисключении двух API. Реальная
сторонняя библиотека этими проверками не тестировалась.

Заключительные ответы не обнаружили новых существенных дефектов исследовательской
процедуры. Claude правильно разобрал все 14 сценариев по инструкциям. Gemini
предложил ненужное уточнение при позднем добавлении третьего; поведение по умолчанию
вынесено также в основной текст. Это наблюдение об ответах на сценарии, не
статистическая оценка надёжности применения скилла.

Claude обнаружил подтверждённый случай: `update --project` без проектного файла
мог изменить личный профиль. Поведение воспроизведено на изолированных профилях
из сохранённой версии кода. Теперь явный проект задаёт место записи и при
отсутствующем файле операция отказывает; личный профиль и профиль окружения
не затрагиваются. `show` и `plan` сохраняют прежний приоритет чтения.
Предложения считать резервную копию при прерванном обновлении дефектом и менять
код выхода для неполной настройки не приняты: копия сохраняет прежние данные,
а состояния уже различаются JSON-ответом и сообщением об ошибке.

Один адресный повторный ответ Gemini проверил три исправленных файла: выбор
места обновления, позднее добавление третьего и разовый запрос «двумя и коротко».
В этих сценариях описано ожидаемое действие без нового существенного замечания.
Итого: два внешних ответа первичного проектирования, десять в исследовании и
один адресный после заключительных поправок. Claude не проверял эти последние
три файла повторно; исправление помощника дополнительно покрыто тестами.

**Автоматически проверено локально: 50 тестов.** Новые проверки покрывают старый
профиль без цикла, независимость числа моделей и цикла, разовые переопределения,
резервную копию и отсутствие изменений при повторном сохранении, ошибки обновления
и явное назначение проектного файла. Прежние проверки транспорта, установки,
ссылок и согласованности версий сохранены. Валидатор скилла также завершился успешно.

Две попытки начать Gemini-исследование остановились до вызова модели: ограниченное
окружение не позволяло проверенному скрипту проверить процесс работающего прокси.
После предоставления необходимого доступа тот же скрипт выполнил вызов. Платный
API-обход не использовался. Сырые ответы, квитанции и пути машины оставлены локально.

Не измерены выигрыш точности, стоимость при равных бюджетах и снижение ошибок
на независимом наборе задач. Внешние модели читали предоставленные тексты и
не выполняли код или тесты. Их согласие с черновиком не является сертификатом
качества или одобрением более поздних непроверенных изменений.

## Выпуск 0.3.1: исправления после настоящего ревью Claude

24 сентября 2026 выполнено ревью четырёх ключевых файлов версии 0.3.0:
`SKILL.md`, конфигурация, протокол и `configure.py`. Роли для этого запуска отдельно
согласованы владельцем: текущий Codex — автор, Claude Fable — рецензент. Провайдер
сообщил `claude-fable-5-1`; запрошено семейство `fable`. Точный ID текущей модели
Codex в этом запуске не зафиксирован. Первая попытка с полным пакетом завершилась
таймаутом без ответа; успешная повторная проверка имела явно сокращённый объём.

Два замечания воспроизведены: помощнику не хватало передачи текущего агента для
роли незаданного оркестратора; `init --project` мог выбрать файл из окружения вместо
явно заданного каталога. Добавлены `--host-file`, отдельный приоритет пути создания
и проверки обоих сценариев, включая сохранность уже выбранных ролей и личного файла.
Уточнены обязанности агента, который только передаёт материалы оркестратору, и
границы проверки совпадающих моделей. Улучшено сообщение о будущей версии схемы.

Предложение различать неполный профиль и ошибку только кодом выхода не принято:
они уже различаются структурированным JSON в stdout и ошибкой в stderr. Замечание
о «трёх ревью» тоже не принято как дефект: у оркестратора два внешних рецензента;
формулировка об их ответах сделана общей. Глобальный флаг допуска одного поставщика
сохранён как явно описанное свойство настройки задачи, без изменения выбора моделей.

Claude анализировал исходный текст без инструментов и не запускал тесты. Исправления
проверяет автоматический набор из 42 тестов; повторное ревью исправленной версии
моделью и живой трёхмодельный прогон не выполнялись. Совместимость `peer.py` и
установщика дополнительно подтверждена отсутствием изменений этих файлов между
версиями, их проверки остаются в общем наборе. Полные ответы и журналы сохранены
локально; в публичный пакет включено только это описание результатов и ограничений.

## Выпуск 0.3.0: два или три участника

Новая конфигурация проверяется локальными тестами: выбор двух/трёх ролей, приоритет
разового запроса, отсутствие скрытого смешивания профилей, сохранение продуктов и
моделей, неизвестные поставщики, отсутствие третьей, повтор одной модели, явный
выбор разных моделей одного поставщика, ошибочные файлы и защита от перезаписи.
Проверяется настоящий запуск помощника настройки в изолированном каталоге.
Прежние тесты транспорта, установки, квитанций и ссылок также сохраняются.

Отдельный агент проверил поведение инструкций на шести сценариях: настройка без
указания числа, другой текущий агент, недоступная третья, разовый запуск двумя,
работа без файла и позднее подключение третьей. По замечаниям уточнены хронология
позднего подключения и приоритет явного выбора моделей одного поставщика.
Это проверка инструкций, а не межпровайдерный эксперимент качества ответов.

Живой трёхмодельный прогон Claude Fable + ChatGPT + Gemini в рамках этого выпуска
не проводился. Доступность аккаунтов и фактические модели не подтверждаются
конфигурацией. Встроенного адаптера Gemini нет: доступны коннектор выбранного
приложения, универсальный адаптер с явной настройкой или ручной обмен.
Прежние модельные эксперименты ниже относятся только к указанным версиям.

## Исправления 0.2.2

Из проверки совпадения моделей убран перечень названий. Семейство Claude читается
из самого сообщённого идентификатора, поэтому новое семейство распознаётся без
правки кода: `claude-fable-5-1` и `claude-nova-1` сверяются так же, как `opus`.
Раньше такие идентификаторы оставались непроверенными, даже когда запрошенная и
сообщённая строки совпадали дословно. Короткий список псевдонимов сохранён только
для отрицательного вердикта — чтобы отличить название семейства от подстановки
вроде `default`; незнакомый псевдоним по-прежнему даёт «не проверено», а не ложное
совпадение. Добавлен тест на семейства, которых нет в коде.

Описан ещё один способ устаревания: помощник разбирает машинный ответ поставщика,
и при смене этого формата вызов завершается как `NOT RUN` с сохранёнными журналами,
а не тихо испорченным ответом.

Происхождение образовательного примера в пилоте названо прямо: это подлинный
фрагмент внутренней работы автора, а не синтетические данные, как в примере про
поддержку. Живых модельных вызовов эта версия не потребовала. Автоматические
тесты прошли на Windows и Linux в GitHub Actions.

## Исправления 0.2.1

На Windows воспроизведено расхождение хешей 0.2.0 с байтами сохранённых файлов.
Теперь квитанция содержит хеши именно записанных UTF-8-байтов `input.md` и
`response.md`; преобразование переводов строк при записи исключено.

Добавлена явная оценка совпадения моделей в квитанции и печатаемой сводке.
Точное совпадение ID отличается от совпадения семейства Claude по короткому
псевдониму. Отсутствующая или неоднозначная идентичность остаётся непроверенной;
явное расхождение даёт код 2 и `NOT RUN`. Полученный ответ сохраняется для разбора.
По нескольким моделям в отчёте расхода автор ответа не угадывается.

Проверка инструкций дополнена сверкой решающих утверждений, с которыми согласны
обе модели. Это устранение пробела в процедуре; эффективность новой формулировки
в отдельном модельном эксперименте пока не измерялась.

Сообщённые провайдером счётчики сохраняются и при неудаче, включая нулевые:
неудачный вызов может иметь стоимость. Статус конверта, если он есть, записан
рядом со счётчиками. Неизвестный расход остаётся неизвестным.

Проверены локальные сценарии помощника с подставными процессами и конвертами,
сохранность хешей, установка в изолированный каталог и внутренние ссылки.
Автоматические тесты этой версии прошли на Windows и Linux в GitHub Actions.
Живых вызовов Claude и Codex для неё не делалось: отчёты о живых запусках ниже
относятся к указанным прежним версиям.

## Пилот 0.2.0 и изменения инструкций

Проведены четыре проверки двух исследовательских примеров: каждый проверяла
та же заявленная модель, что подготовила черновик, и другая модель. Отдельный
контроль проверял принятие верной и отклонение ложной поправки. Всего пять
завершённых вызовов из шести; контроль Claude — NOT RUN из-за лимита аккаунта.

Обе модели исправили охват сравнения 68 → 12 курсов и сохранили оговорку в
рекомендации об интерфейсе. Обе также приписали исходнику более сильный причинный
вывод, чем он явно содержал. Это не доказательство преимущества какой-либо модели.
Опубликованы [план, ответы, ограничения и разбор](../evaluations/2026-09-pilot/results.md).

Инструкции требуют проверить сохранность поправок после сведения ответов и
сравнить вклад рецензента с исходным ответом. По итогам пилота добавлено короткое
правило: проверять реальное утверждение и не выдумывать отклонённые возражения.
Последняя формулировка отдельно на моделях не проверялась.

Помощник сохраняет доступные счётчики расхода провайдера. Неизвестный расход
не превращается в ноль; счётчики разных провайдеров не объявляются общей мерой
стоимости. История исследования и оформление GitHub находятся вне скилла.

## Что показал пример

Обе модели обнаружили разный состав заявок и отсутствие доказанного причинного
эффекта ИИ. Арифметика проверена отдельно. Codex добавил альтернативы о возможной
пользе вне времени решения и различиях внутри категорий сложности.

В одном ответе Claude были неподтверждённые обобщения о респондентах и произвольные
численные требования к будущему пилоту. Они не становятся верными из-за успешного
вызова и не перенесены в [проверенный разбор](../examples/research/worked-example.md).
Формулировку итогового Claude «опрос ничего не добавляет» тоже нужно сузить:
опрос описывает ответивших, но не позволяет оценить долю довольных среди всех.

Первый ответ ведущего агента уже содержал основной дефект. Пример подтверждает
работу обмена и показывает дополнительные соображения, но **не доказывает
превосходство двух моделей над одной**. Для этого нужен отдельный эксперимент
с сопоставимым бюджетом и заранее заданными критериями.

## Автоматические проверки текущего выпуска

Автоматические тесты не требуют платных модельных вызовов:

```text
python -m unittest discover -s tests -v
```

Проверяются полный бриф и буквальные аргументы без shell-интерпретации; пустой
ответ; ошибка процесса; таймаут; защита существующих результатов; корректность
ответов Claude и Codex; отказ на некорректном событии; установка, дрейф и резервная
копия; локальные ссылки; арифметика примера; сохранение единиц расхода провайдера
и обработка отсутствующих или некорректных счётчиков. Дополнительно проверяются
совпадение хешей с байтами файлов при BOM/CRLF, совпадение и расхождение моделей,
неоднозначные отчёты о моделях, расход неудачных вызовов и абсолютный путь
исполняемого файла при смене рабочего каталога. Структура skill и plugin
проверяется отдельно. [Первый прогон GitHub Actions для 0.1.0](https://github.com/chu-st/skills/actions/runs/34321808324)
успешно завершил все четыре сочетания: Windows и Linux, Python 3.10 и 3.12.

## Пока не подтверждено

- Живой вызов другого провайдера через общий адаптер: проверен контракт доставки
  на локальном процессе, но не конкретный сторонний сервис.
- Полный ручной сценарий между сторонними веб-чатами.
- Живые CLI-вызовы на macOS и Linux, старые версии клиентов, корпоративные
  окружения и самостоятельный поиск источников обеими моделями.
- Средняя точность, экономия и отсутствие общих ошибок моделей.

воспроизводятся по открытому брифу; `receipt.json` связывает ответ с входом и
