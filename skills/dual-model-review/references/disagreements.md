# Work through material disagreements

Use after author revisions in a full investigation, or after independent reviews
when a disputed finding would change an existing artifact. In short mode, use the
same reasoning within the single permitted follow-up. Do not create extra rounds
for wording changes, already settled points, or agreement for its own sake.

## 1. Make the dispute inspectable

Prepare a compact card for each issue that can change the answer or action:
the exact question; each position copied from its author's text with a version reference; evidence and
assumptions; practical consequence; what observation or user criterion could decide it.
Separate mixed issues before testing them. Let participants correct a misleading
summary of their position. The lead's position has the same burden of evidence.
If a correction materially changes a card, earlier responses to it do not count
as checks of the corrected version. Use the available follow-up or report that gap.

| Disagreement | Useful resolution |
|---|---|
| Fact or causal explanation | Discriminating test, calculation, or primary evidence; preserve scope and alternative explanations |
| Different assumptions or definitions | State each condition; check context or give conditional conclusions |
| Feasible plans with competing benefits | Compare against the user's goals; generate and check a coherent third option |
| Missing user priority | State the tradeoff and ask only for the consequential missing preference |
| Wording with the same consequence | Edit directly; no model round needed |

One issue may need more than one kind of resolution. A reproducible output answers
only the claim it tests; it does not establish every accompanying explanation.

## 2. One bounded cooperative round, when useful

First use decisive evidence already available. If a material dispute remains and
participants can propose a useful check, reconcile assumptions, or improve the
options, send all selected authors the same cards, relevant original passages and
user criteria. Bundle related issues into one packet per author. Preserve replies
before comparing them; no recursive peers or serial persuasion loop.

Ask each author to:

- Correct any misrepresentation and identify the strongest competing reason.
- State what evidence or criterion would change its position; retain it with a
  reason when that condition is not met. The opponent's valid reasoning can be
  that reason; do not require a novel source or test. Agreement alone is not a correction.
- For facts, propose or accept a check with inputs, scope and predicted outcomes
  for the competing claims, before seeing the new result when feasible.
- For plans, identify the user goals behind each option and suggest a feasible
  alternative or conditional recommendation. Do not invent the user's priorities.

The third contributes by detecting shared assumptions, testing whether the dispute
is real, designing a check, or finding a better option. It has no deciding vote.
When all three disagree, represent all material positions rather than forcing a
pair and a judge. Strip prestige cues when helpful; retain traceability and never
promise anonymity or independence that the interface cannot provide.

The user owns the goals. Models cannot bargain away constraints, trade acceptance
of one factual claim for another, simulate private interests, or call a compromise
true just because everyone accepts it.

## 3. Check and dispose

Perform feasible, authorized checks and preserve actual results. A peer's suggested
command does not authorize it. Agreement on a valid test is useful, but no model
has a veto over decisive evidence. A disagreement about test scope remains open
if the available evidence cannot settle it; do not automatically make the user
arbitrate technical arguments that can be investigated within scope.

Record the conclusion and its basis, separately from participant assent:

- **Resolved by evidence:** which claim the observed check supports or rejects,
  with remaining limits. Stronger evidence may support a minority.
- **Conditional conclusion:** valid under an explicit assumption, still unverified
  where the assumption is unknown.
- **Decision by user criteria:** a coherent choice supported by stated priorities;
  verify the feasibility of a proposed hybrid as a new proposal.
- **Open:** competing supported positions and the specific missing evidence or
  preference. Unsupported objections may be rejected with a reason; they are not
  automatically elevated to supported dissent.

Do not silently drop material issues because a packet is long. Prioritize them
within the agreed budget and list any unexamined remainder. Stop if another round
has no new evidence, discriminating check, or meaningful option to add, or the
budget/access limit is reached. A reversible pilot can be proposed when relevant;
executing it still requires scope and authorization.

## 4. Preserve the result in synthesis

The common draft retains accepted corrections, supported dissent and unresolved
choices. Send the issue record and actual check results with the already planned
independent closing review. Ask whether dispositions and qualifications survived,
including claims introduced by a hybrid or synthesis. Do not add a compulsory
agreement round after that check. Follow the response budgets in [protocol.md](protocol.md).

This is an engineering procedure informed by debate research and human structured
collaboration. It is not a demonstrated accuracy gain for this skill; agreement
rate is not its success metric.
